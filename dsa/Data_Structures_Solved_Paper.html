Explain Big O notation with example. Describe Time and Space Complexity.
Q15 marks
Key idea: Big O gives an upper bound on how fast the running time (or memory) of an algorithm grows as the input size n grows. It ignores constants and lower-order terms.
1
Definition
f(n) = O(g(n)) if there exist constants c > 0 and n₀ ≥ 1 such that f(n) ≤ c · g(n) for all n ≥ n₀. We say g(n) is an asymptotic upper bound of f(n).
2
Worked example
Show that f(n) = 3n² + 2n + 5 is O(n²).
Choose c = 4. We need 3n² + 2n + 5 ≤ 4n², i.e. 2n + 5 ≤ n².
n = 3: 11 ≤ 9 ✗   n = 4: 13 ≤ 16 ✓ and it stays true for larger n.
So with c = 4, n₀ = 4: f(n) ≤ 4n² for all n ≥ 4 ⇒ f(n) = O(n²).
3
Common growth rates (slowest to fastest)
Big ONameExample
O(1)constantarray access a[i]
O(log n)logarithmicbinary search
O(n)linearlinear search, traversing a list
O(n log n)linearithmicmerge sort
O(n²)quadraticbubble sort, two nested loops
O(2ⁿ)exponentialnaive subset generation
4
Time complexity
Time complexity = the number of basic operations an algorithm performs, expressed as a function of the input size n (not seconds, which depend on the machine). It is analysed as best case (Ω), average case (Θ) and worst case (O).
Example: for i = 1 to n: sum = sum + a[i] runs the addition n times ⇒ T(n) = O(n). Two nested loops over n give n × n ⇒ O(n²).
5
Space complexity
Space complexity = the total memory an algorithm needs as a function of n: the input plus the auxiliary (extra) space such as temporary variables, arrays, recursion stack.
Example: summing an array uses only sum and i ⇒ O(1) auxiliary space. Merge sort needs a temporary array of size n ⇒ O(n). Recursive factorial uses n stack frames ⇒ O(n).
∴ Big O = upper bound on growth; time complexity counts operations, space complexity counts memory, both as functions of n.

(i)(b)
Write algorithm / pseudocode to implement infix to postfix.
Q210-mark question (parts a + b)
Key idea: Scan the infix expression left to right. Operands go straight to the output. Operators are pushed on a stack, but first pop any operator on the stack with higher or equal precedence. "(" is pushed; ")" pops until "(". Precedence: ^ (3, right-assoc.) > * / (2) > + − (1).
1
Algorithm
  1. Create an empty stack S and an empty output string P.
  2. For each token ch of the infix expression from left to right:
    1. if ch is an operand (letter or digit): append it to P;
    2. if ch is "(": push it on S;
    3. if ch is ")": pop operators from S to P until "(" is found, then discard "(";
    4. if ch is an operator: while S is not empty, the top is not "(", and prec(top) ≥ prec(ch) [for "^" use >]: pop top to P. Then push ch.
  3. After the last token, pop all remaining operators from S to P.
  4. P is the postfix expression.
2
Pseudocode
InfixToPostfix(infix):
    create empty stack S
    postfix = ""
    for each character ch in infix:
        if ch is an operand:
            postfix = postfix + ch
        else if ch == '(':
            push(S, ch)
        else if ch == ')':
            while top(S) != '(':
                postfix = postfix + pop(S)
            pop(S)                      // discard '('
        else:                           // ch is an operator
            while S is not empty and top(S) != '(' and
                  prec(top(S)) >= prec(ch):
                postfix = postfix + pop(S)
            push(S, ch)
    while S is not empty:
        postfix = postfix + pop(S)
    return postfix

Write an algorithm / pseudocode to implement the following functions for a static Circular Queue using array: (a) Enqueue (b) Dequeue (c) Display all elements (d) Check for Circular full condition.
Q210 marks (alternative to Q2 (i))
Key idea: A circular queue treats the array as a ring: after the last index the next position is index 0. Use front and rear with modulo N arithmetic, N = array size. Initially front = rear = −1 (empty).
1
Declarations
#define N 5                 // capacity
int Q[N];
int front = -1, rear = -1;  // -1 means the queue is empty
2
(d) Circular full condition
The queue is full when the next position after rear is front:
isFull: (rear + 1) mod N == front
Empty: front == −1.
isFull():
    return (rear + 1) % N == front

isEmpty():
    return front == -1
3
(a) Enqueue
Enqueue(x):
    if isFull():
        print "Queue Overflow"
        return
    if front == -1:             // first element
        front = 0
    rear = (rear + 1) % N       // wrap around
    Q[rear] = x
4
(b) Dequeue
Dequeue():
    if isEmpty():
        print "Queue Underflow"
        return
    x = Q[front]
    if front == rear:           // last element removed
        front = rear = -1
    else:
        front = (front + 1) % N // wrap around
    return x
5
(c) Display all elements
Display():
    if isEmpty():
        print "Queue is empty"
        return
    i = front
    while true:
        print Q[i]
        if i == rear:
            break
        i = (i + 1) % N

(i)(a)
Construct AVL Tree for the following data: 3, 6, 7, 8, 2, 1
Q310-mark question (parts a + b)
Key idea: An AVL tree is a BST in which, for every node, the balance factor BF = height(left) − height(right) is −1, 0 or +1. After each insertion, if some node has |BF| = 2, fix it by a rotation: LL → right rotation, RR → left rotation, LR → left then right, RL → right then left. The numbers beside the nodes below are the balance factors.
1
Insert 3, then 6
Insert 3 (root). 6 > 3 so it goes to the right. BF(3) = 0 − 1 = −1, allowed.
2
Insert 7: imbalance at 3
Path: 7 > 3, 7 > 6 ⇒ right child of 6. Heights: node 6 has BF −1; node 3 has left height 0, right height 2 ⇒ BF(3) = −2. The new node is in the right subtree of the right child: the RR case ⇒ left rotation at 3.
3
Left rotation at 3
Node 6 (the right child of 3) becomes the root of this subtree; 3 becomes its left child; 6's old left subtree (empty) becomes 3's right subtree.
4
Insert 8
8 > 6, 8 > 7 ⇒ right child of 7. BF(7) = −1, BF(6) = 1 − 2 = −1, BF(3) = 0: no node has |BF| = 2, so no rotation.
5
Insert 2
2 < 6, 2 < 3 ⇒ left child of 3. BF(3) = +1, BF(6) = 2 − 2 = 0. Balanced.
6
Insert 1: imbalance at 3
1 < 6, 1 < 3, 1 < 2 ⇒ left child of 2. Node 3: left height 2, right height 0 ⇒ BF(3) = +2. The new node is in the left subtree of the left child: the LL case ⇒ right rotation at 3.
7
Right rotation at 3
Node 2 (the left child of 3) becomes the subtree root; 3 becomes its right child; 2's old right subtree (empty) becomes 3's left subtree. Check: BF(2) = 0, BF(7) = −1, BF(6) = 2 − 2 = 0, all within ±1.
∴ Final AVL tree: root 6 with left subtree 2 (children 1 and 3) and right subtree 7 (right child 8). Two rotations were used: left at 3, then right at 3. Inorder = 1, 2, 3, 6, 7, 8 (sorted) ✓.

(ii)
Write algorithm / pseudocode for delete function of Binary Search Tree.
Q310 marks (alternative to Q3 (i))
Key idea: Deleting a node from a BST has three cases, depending on how many children the node has. The BST property (left < node < right) must be kept.
1
The three cases
CaseNode to deleteAction
1Leaf (no child)Remove it: set the parent's pointer to NULL
2One childReplace the node by its child (parent now points to the child)
3Two childrenFind the inorder successor (smallest node of the right subtree) [or inorder predecessor], copy its value into the node, then delete that successor (it has at most one child)
2
Algorithm (C style): node temp is the node to delete, parent is its parent
if (temp->left == NULL && temp->right == NULL) {      // Case 1: leaf
    if (parent->left == temp)  parent->left  = NULL;
    else                       parent->right = NULL;
    free(temp);
}
else if (temp->left == NULL || temp->right == NULL) {  // Case 2: one child
    struct node *child;
    if (temp->left != NULL)  child = temp->left;
    else                     child = temp->right;
    if (parent->left == temp)  parent->left  = child;
    else                       parent->right = child;
    free(temp);
}
else if (temp->left != NULL && temp->right != NULL) {  // Case 3: two children
    struct node *ins;          // (inorder successor)
    struct node *ins_parent;
    ins = temp->right;
    ins_parent = temp;
    while (ins->left != NULL) {
        ins_parent = ins;
        ins = ins->left;
    }
    temp->data = ins->data;
    if (ins_parent->left == ins) {
        ins_parent->left = ins->right;
    } else {
        ins_parent->right = ins->right;
    }
    free(ins);
}
3
How Case 3 works
  1. ins = temp->right: go to the right subtree.
  2. Keep going left (while ins->left != NULL) while remembering the parent in ins_parent: this finds the inorder successor (smallest node of the right subtree).
  3. Copy its data into the node: temp->data = ins->data.
  4. Unlink the successor: it has no left child, so its parent takes over ins->right (as the left child if ins_parent->left == ins, else as the right child).
  5. free(ins).
4
Example
BST built from 50, 30, 70, 20, 40, 60, 80.Delete 20 (leaf): removed.
Delete 30 (now has only the right child 40): replaced by 40.
Delete 50 (two children): inorder successor = smallest in right subtree = 60; copy 60 to the root, then delete the leaf 60 from the right subtree.
∴ Search for the key, then handle leaf / one-child / two-children (inorder successor); time O(h), O(log n) for a balanced tree, O(n) worst case.

Describe Hash Table data structure. Explain Hash Collision with example? Explain different Hash Collision techniques with example.
Q410 marks
1
Hash table
A hash table stores (key, value) pairs in an array of size M. A hash function h(k) converts a key into an array index (a "bucket"), so insert, search and delete take O(1) average time. Example hash function (division method): h(k) = k mod M. A good hash function is fast, spreads keys uniformly, and gives the same index for the same key. Load factor α = n / M (keys stored ÷ table size).
2
Hash collision
A collision occurs when two different keys give the same hash index.
Example: M = 10, h(k) = k mod 10: keys 23 and 43 both give index 3. The table cannot store both at index 3, so a collision resolution technique is needed.
3
Techniques
Use the keys 23, 43, 13, 27, 47 inserted in this order into a table of size M = 10 (23, 43 and 13 all hash to 3; 27 and 47 both hash to 7).
4
(A) Separate chaining (open hashing)
Each bucket holds a linked list of all keys that hash to it. Colliding keys are simply appended to the list.
IndexChain
323 → 43 → 13
727 → 47
Pros: never "full", simple deletion. Cons: extra memory for pointers.
5
(B) Open addressing: linear probing
If the slot is taken, try the next one: index = (h(k) + i) mod M, i = 0, 1, 2, …
43: slot 3 full → 4 ✓; 13: 3, 4 full → 5 ✓; 27 → 7 ✓; 47: 7 full → 8 ✓.

index = (h(k) + i²) mod M.
43: 3 full → 3 + 1 = 4 ✓; 13: 3 full, 4 full, 3 + 4 = 7 ✓ (27 not yet inserted); 27: 7 full → 7 + 1 = 8 ✓; 47: 7 full, 8 full, 7 + 4 = 11 mod 10 = 1 ✓.

43: h₂ = 7 − 1 = 6 → 3 + 6 = 9 ✓; 13: h₂ = 7 − 6 = 1 → 4 ✓; 27 → 7 ✓; 47: h₂ = 7 − 5 = 2 → 7 + 2 = 9 full → 7 + 4 = 11 mod 10 = 1 ✓.

Differentiate between Linear and Binary Search techniques. Write an algorithm / pseudocode to implement Binary Search Technique.
Q510 marks
1

2
Binary search algorithm
  1. Set low = 0 and high = n − 1.
  2. While low ≤ high: mid = (low + high) / 2 (integer division).
    • If A[mid] == key: return mid (found).
    • If A[mid] < key: search the right half, low = mid + 1.
    • Otherwise search the left half, high = mid − 1.
  3. If the loop ends, the key is not present: return −1.
3
Pseudocode (iterative)
BinarySearch(A, n, key):          // A is sorted in ascending order
    low  = 0
    high = n - 1
    while low <= high:
        mid = low + (high - low) / 2      // integer division, avoids overflow
        if A[mid] == key:
            return mid                    // found at index mid
        else if A[mid] < key:
            low = mid + 1                 // go right
        else:
            high = mid - 1                // go left
    return -1                             // not found
4
Recursive version
BinarySearchRec(A, low, high, key):
    if low > high:
        return -1
    mid = (low + high) / 2
    if A[mid] == key:   return mid
    if A[mid] <  key:   return BinarySearchRec(A, mid + 1, high, key)
    return BinarySearchRec(A, low, mid - 1, key)
