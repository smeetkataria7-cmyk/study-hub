Sorting, Searching & Hashing

Order the data, then find things in it quickly.
8.1

Sorting concepts

  • Stable: equal keys keep their original order. In place: needs only O(1) extra memory. Internal: data fits in memory.
8.2

Bubble sort

comparisons  n(n − 1)2

Compare adjacent elements and swap if out of order; after pass i the i-th largest is in place. With a swapped-flag it stops early on sorted data.

8.3

Counting sort

time  O(n + k)

For integers in 0..k: count each value, take cumulative counts (they give final positions), then place elements from right to left to stay stable. Not comparison based.

8.4

Heap sort

children of i  2i + 1,   2i + 2,   parent  ⌊(i − 1)/2⌋
  • Max-heap: every parent ≥ its children; the root is the largest.
  • Build heap: heapify from the last internal node (index n/2 − 1) up to 0: O(n).
  • Sort: swap root with the last element, shrink the heap, heapify the root: n times O(log n).

8.6

Linear search

O(n)

Check elements one by one. Works on unsorted data. Average comparisons (n + 1)/2.

8.7

Binary search

mid = ⌊(low + high) / 2⌋O(log n)

Needs a sorted array. Compare the key with the middle: equal → found; smaller → search the left half; larger → the right half. Maximum comparisons ⌊log₂ n⌋ + 1.

8.8

Hashing

h(k) = k mod Mload factor  α = nM

A hash function maps a key to a table index; a collision happens when two keys map to the same index. A good function is fast and spreads keys evenly; M is usually prime.

A short self-learning topic and exam reminders.
9.1

Sparse matrix (self-learning)

A matrix with mostly zero entries. Store only the non-zero elements as triplets (row, column, value), plus a header row (rows, columns, count). Saves space and speeds up addition.

  • Addition: merge the two triplet lists in row-major order; at the same position add the values (drop zero results).
  • Space: 3 × (non-zero count + 1) instead of rows × columns.
9.2

Quick exam reminders

  • Always state the base case for recursion and the empty / full conditions for stack and queue.
  • Draw the structure before and after each insert or delete.
  • For AVL and hashing, show every step with balance factors or probe sequences.
  • Write algorithms in C style, as in class (struct node *, ->, free()).
Q

Theory questions and model answers

Tap "Show model answer" to reveal.
Q1

Explain bubble sort with its complexity.

Show model answer

Compare adjacent elements and swap if out of order; each pass bubbles the largest unsorted element to the end. n − 1 passes, n(n − 1)/2 comparisons: O(n²) worst and average, O(n) best with a swapped flag; stable and in place.

Q2

Explain counting sort.

Show model answer

For integers in 0..k: count occurrences, form cumulative counts (final positions), then place elements from right to left. O(n + k) time, O(k) extra space, stable, not comparison based.

Q3

Explain heap sort.

Show model answer

Build a max-heap (heapify from index n/2 − 1 to 0, O(n)); repeatedly swap the root with the last element, shrink the heap and heapify the root. O(n log n) always, in place, not stable.

Q4

Compare linear and binary search.

Show model answer

Linear search checks elements one by one: O(n), works on unsorted data. Binary search needs a sorted array and halves the range each step: O(log n), at most ⌊log₂ n⌋ + 1 comparisons.

Q5

What is hashing? Explain collision resolution techniques.

Show model answer

Hashing maps a key to a table index with h(k) = k mod M. Collisions are resolved by separate chaining (linked list per slot) or open addressing: linear probing (h + i) mod M, quadratic probing (h + i2) mod M and double hashing (h1 + i h2) mod M.

Q6

What is rehashing?

Show model answer

When the load factor α = n/M gets too high, create a table about twice as large (next prime), and reinsert every key with the new hash function. It costs O(n) but keeps operations fast.
