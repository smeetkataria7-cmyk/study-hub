Indexing & query processing

B-trees, hashing, query cost and optimisation.
4.1

Basic concepts of indexing

An index is a small structure (search key, pointer) that speeds up searching a file. Evaluate indexes by access time, insertion and deletion time and space.

4.2

Ordered indices

TypeMeaning
Primary (clustering) indexOn the field that sorts the file; one per file
Secondary indexOn a non-ordering field; always dense; many per file
Dense indexAn index entry for every search-key value
Sparse indexEntry only for some values (one per block); needs a sorted file
Multilevel indexAn index on the index, until the top level fits in one block
4.3

Dense vs sparse

  • Dense: faster to locate a record directly, supports existence tests, more space and update cost.
  • Sparse: smaller and cheaper to maintain; find the largest key ≤ the search key, then scan the block.
4.4

B-tree (order m)

  • A balanced, multiway search tree: all leaves at the same level; every node holds sorted keys.
  • Max children m, max keys m − 1. Min children ⌈m/2⌉ for non-root internal nodes (min keys ⌈m/2⌉ − 1); the root has at least 2 children.
  • Search: at each node find the interval containing the key and follow that child; O(log n) block reads.
  • Insert: insert into the right leaf; if it overflows, split at the median and push the median key up (the tree grows at the root).
  • Delete: remove the key (replace by the inorder successor in an internal node); if a node underflows, borrow from a sibling or merge with it.
4.5

B+ tree

  • All records / data pointers are in the leaves, linked in order for fast range scans; internal nodes hold only search keys.
  • Higher fan-out than a B-tree (no data pointers in internal nodes) so it is shorter; the usual index structure in databases.
4.6

Hashing

  • A hash function h(K) maps a key to a bucket (disk block); an equality search costs about one block access.
  • Static hashing: fixed bucket count; collisions go to overflow buckets.
  • Dynamic hashing (extendible, linear) grows the directory / buckets as data grows.
4.7

4.8

Query processing: steps

  • Parsing and translation (check syntax, build relational algebra expression) → optimisation (choose the cheapest evaluation plan) → evaluation (the engine executes the plan).
4.9

Measures of query cost

cost  b × tT + S × tS

b = blocks transferred, S = random seeks, tT = block transfer time, tS = seek time. Cost is dominated by disk accesses; CPU cost is usually ignored.

4.10

Algorithms for SELECT

  • A1 linear scan: read every block, cost br (half on average for a key equality, as it stops when found).
  • A2 binary search (sorted file, equality on the ordering field): ⌈log₂ b_r⌉ blocks.
  • A3 primary index, equality on key: hi + 1 block accesses (hi = index height).
  • Secondary index and range queries (use the B+ tree leaf chain); conjunctions use one index then filter, or index intersection.
4.11

Algorithms for PROJECT

Project each tuple, then eliminate duplicates by sorting or hashing (cost of an external sort); if the projection includes a key there are no duplicates.

4.12

Query optimisation: equivalence rules

  • Cascade of σ: σc1 ∧ c2(R) = σc1(σc2(R)); selections commute.
  • Cascade of π: only the last projection matters.
  • Selection push-down: σc(R ⋈ S) = σc(R) ⋈ S if c uses only R attributes.
  • Join is commutative and associative; σ over × with a join condition becomes a join.
  • Heuristics: do selections and projections early to shrink intermediate results; choose the join order with the smallest intermediate sizes.
4.13

fr = ⌊block sizerecord size⌋,   br = ⌈nrfr⌉equality selection size  nrV(A, r)

nr = number of tuples, fr = tuples per block, br = blocks, V(A, r) = number of distinct values of A. The optimiser generates alternative plans, estimates the cost of each from such statistics and picks the cheapest (cost-based); EXPLAIN shows the chosen plan.

Q

Theory questions and model answers

Tap "Show model answer" to reveal.
Q1

Differentiate dense and sparse indexes.

Show model answer

A dense index has an entry for every search-key value; a sparse index only for some (one per block) and needs a sorted file. Dense is faster for direct lookups; sparse is smaller and cheaper to maintain.

Q2

Explain the B-tree and its properties.

Show model answer

A balanced multiway tree with all leaves at one level. Order m: at most m children and m − 1 keys; non-root nodes have at least ⌈m/2⌉ children. Search O(log n); an overflowing node splits and the median moves up; underflow is fixed by borrowing or merging.

Q3

How does a B+ tree differ from a B-tree?

Show model answer

In a B+ tree all data pointers are in the leaves, which are linked for range scans; internal nodes hold only keys, so the fan-out is higher and the tree is shorter.

Q4

Compare ordered indexing and hashing.

Show model answer

Ordered indices support range queries and sorted access in O(log n); hashing gives O(1) equality lookups but no range or order queries and needs overflow handling.

Q5

What are the steps in query processing?

Show model answer

Parsing and translation to relational algebra, optimisation (choosing the cheapest plan from cost estimates), and evaluation by the execution engine.

Q6

State the equivalence rules used in query optimisation.

Show model answer

Cascade and commutativity of selection, cascade of projection, commutativity and associativity of joins, and pushing selections and projections down. Heuristic: do selections and projections early and choose small intermediate results.

P1

B-tree insertion

Insert 10, 20, 30, 40, 50, 60, 70, 80 into an empty B-tree of order 4 (maximum 3 keys per node). Show the tree after each insertion.

Show solution
  1. insert 10 → [10]
  2. insert 20 → [10 20]
  3. insert 30 → [10 20 30]
  4. insert 40 → [20 → [10], [30 40]] (split: 20 moves up)
  5. insert 50 → [20 → [10], [30 40 50]]
  6. insert 60 → [20 40 → [10], [30], [50 60]] (split: 40 moves up)
  7. insert 70 → [20 40 → [10], [30], [50 60 70]]
  8. insert 80 → [20 40 60 → [10], [30], [50], [70 80]] (split: 60 moves up)
Final tree: [20 40 60 → [10], [30], [50], [70 80]] (full nodes are split before descending; the only root split happened when 40 arrived, giving two levels).
P2

Index sizing

A file has 100,000 records in blocks of 50 records. The search key is 8 bytes, a pointer 4 bytes, and a block is 4096 bytes. Find the file blocks, the dense and sparse primary-index entries and blocks, and the number of index levels.

Show solution
  1. File blocks = 100,000 / 50 = 2000.
  2. Dense index: 100,000 entries; entries per index block = ⌊4096 / 12⌋ = 341 → ⌈100,000 / 341⌉ = 294 blocks.
  3. Sparse index: one entry per file block = 2000 entries → ⌈2000/341⌉ = 6 blocks.
  4. Multilevel: level 1 (sparse) has 6 blocks; level 2 needs 6 entries → 1 block, so 2 index levels.
File 2000 blocks; dense index 294 blocks; sparse index 6 blocks (2 levels with a single top block).
P3

Static hashing

Hash function h(k) = k mod 4, bucket capacity 2. Insert 8, 12, 5, 9, 16, 13, 4, 20. Show the buckets.

Show solution
  1. 8 → 0, 12 → 0, 5 → 1, 9 → 1, 16 → 0 (bucket 0 full: overflow), 13 → 1 (bucket 1 full: overflow), 4 → 0 (overflow), 20 → 0 (overflow).
  2. Bucket 0: 8, 12 | overflow: 16, 4 | overflow: 20.
  3. Bucket 1: 5, 9 | overflow: 13.
  4. Buckets 2 and 3 are empty.
Skewed keys cause long overflow chains in static hashing, which dynamic (extendible) hashing avoids.
P4

Cost of selection algorithms

A relation has 2000 blocks and 100,000 records sorted on key K. Estimate the block accesses for an equality search on K with (a) linear scan (average), (b) binary search, (c) a primary B+ tree index of height 3.

Show solution
  1. (a) Linear scan, key found on average halfway: 2000 / 2 = 1000 blocks (worst case 2000).
  2. (b) Binary search: ⌈log₂ 2000⌉ = 11 blocks.
  3. (c) B+ tree: height + 1 = 3 + 1 = 4 blocks.
About 1000, 11 and 4 block accesses; the index is far cheaper.
P5

Query optimisation with sizes

Student (10,000 tuples) is joined with Enrol (50,000 tuples) and then σ(dept = CSE) is applied, where CSE holds 5% of students and the condition is on Student only. Compare the plan with the selection last and the plan with the selection pushed down.

Show solution
  1. Plan 1: join first: intermediate result ≈ 50,000 tuples (every Enrol row matches one student), then select → about 2,500 tuples; the join processes 10,000 × 50,000 pairs by nested loops or similar.
  2. Plan 2: σ first: Student shrinks to 5% × 10,000 = 500 tuples; join 500 with Enrol: the intermediate result is about 2,500 and the join input is 20 times smaller on the Student side.
Pushing the selection down gives the same answer with far less work, since the join reads 500 instead of 10,000 Student tuples.
P6

Index choice

Which index suits (a) WHERE roll = 17, (b) WHERE cgpa BETWEEN 7 AND 9, (c) ORDER BY name?

Show solution
  1. (a) Equality on a key: hash index or B+ tree (hash is O(1)).
  2. (b) Range: B+ tree (leaf chain); a hash index cannot do ranges.
  3. (c) Sorted output: B+ tree on name (hash gives no order).
(a) hash or B+ tree, (b) B+ tree, (c) B+ tree.
