Models & SQL

ER modelling, the relational model, relational algebra and SQL.
2.1

Database design phases

  • Requirements analysis → conceptual design (ER model) → logical design (map to relations, normalise) → physical design (indexes, storage) → implementation and maintenance.
2.2

ER model: entities and attributes

  • Entity (rectangle) is a distinguishable object; an entity set is a collection of them. Weak entity (double rectangle) has no key of its own and depends on an owner through an identifying relationship; it has a partial key.
  • Attribute (ellipse): simple / composite, single-valued / multivalued (double ellipse), derived (dashed), key (underlined).
2.3

Relationships and constraints

  • Relationship (diamond) links entities; degree = number of entity sets (binary, ternary).
  • Cardinality: one-to-one, one-to-many, many-to-one, many-to-many.
  • Participation: total (double line, every entity takes part) or partial.
  • Key constraints decide the relation's primary key.
2.4

Extended ER features

  • Specialisation (top-down) and generalisation (bottom-up) with ISA and attribute inheritance.
  • Constraints: disjoint vs overlapping; total vs partial completeness.
  • Aggregation: treat a relationship as an entity so another relationship can involve it.
2.5

ER design issues

  • Entity set vs attribute; entity set vs relationship set; binary vs ternary relationships.
  • Avoid redundant attributes and unnecessary weak entities; place attributes on the entity that owns them.
2.6

Relational model concepts

A relation is a table: tuples (rows) and attributes (columns), each attribute with a domain. Degree = number of attributes, cardinality = number of tuples. A relation is a set, so rows are unordered and distinct.

2.8

Integrity constraints

  • Domain: values come from the attribute domain (type, CHECK).
  • Entity integrity: no primary-key attribute is NULL.
  • Key: no two tuples have the same key value.
  • Referential integrity: a foreign-key value is NULL or equals an existing primary-key value; actions ON DELETE / ON UPDATE (CASCADE, SET NULL, RESTRICT).

2.12

SQL: data definition and constraints

  • CREATE / ALTER / DROP TABLE, TRUNCATE, CREATE INDEX.
  • Attribute constraints: NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY ... REFERENCES, CHECK, DEFAULT.
  • Types: INT, DECIMAL, CHAR(n), VARCHAR(n), DATE, ...
2.13

SQL: tables, insert, update, delete

CREATE TABLE Student (
    roll    INT PRIMARY KEY,
    name    VARCHAR(40) NOT NULL,
    dept_id INT,
    cgpa    DECIMAL(3,2) CHECK (cgpa BETWEEN 0 AND 10),
    FOREIGN KEY (dept_id) REFERENCES Dept(dept_id)
        ON DELETE SET NULL
);
INSERT INTO Student VALUES (1, 'Asha', 10, 8.5);
UPDATE Student SET cgpa = cgpa + 0.1 WHERE dept_id = 10;
DELETE FROM Student WHERE cgpa < 4;
ALTER TABLE Student ADD email VARCHAR(60);
2.14

SQL: query clauses and logical order

SELECT   dept_id, COUNT(*) AS n, AVG(cgpa) AS avg_cgpa
FROM     Student
WHERE    cgpa > 6
GROUP BY dept_id
HAVING   COUNT(*) > 5
ORDER BY avg_cgpa DESC;

Logical order of evaluation: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. WHERE filters rows before grouping; HAVING filters groups.

2.15

SQL: joins, set operations, aggregates, NULL

SELECT s.name, d.dept_name
FROM Student s JOIN Dept d ON s.dept_id = d.dept_id;      -- also LEFT / RIGHT / FULL OUTER JOIN

SELECT name FROM A UNION SELECT name FROM B;               -- INTERSECT, EXCEPT (MINUS); UNION ALL keeps duplicates

SELECT COUNT(*), SUM(cgpa), AVG(cgpa), MIN(cgpa), MAX(cgpa) FROM Student;

SELECT * FROM Student WHERE dept_id IS NULL;               -- never use = NULL

NULL means unknown: any comparison with NULL is unknown, so use IS NULL. Aggregates (except COUNT(*)) ignore NULLs.

2.16

SQL: nested subqueries, views, data control

SELECT name FROM Student
WHERE cgpa > (SELECT AVG(cgpa) FROM Student);              -- scalar subquery

SELECT name FROM Student s
WHERE EXISTS (SELECT 1 FROM Enrol e WHERE e.roll = s.roll);  -- correlated subquery

SELECT name FROM Student
WHERE dept_id IN (SELECT dept_id FROM Dept WHERE city = 'Mumbai');   -- also ANY, ALL, NOT IN

CREATE VIEW TopStudents AS SELECT * FROM Student WHERE cgpa > 9;

GRANT SELECT, UPDATE ON Student TO user1;
REVOKE UPDATE ON Student FROM user1;

A view is a stored query (virtual table): it simplifies queries, hides columns (security) and gives logical data independence.

2.17

Integrity and security: triggers and authorisation

  • Referential integrity and domain constraints (see 2.8) are enforced by the DBMS.
  • Trigger: code run automatically on an event (INSERT, UPDATE, DELETE) when a condition holds, BEFORE or AFTER it; used for audit logs and derived data.
  • Authorisation: privileges (SELECT, INSERT, UPDATE, DELETE, REFERENCES) granted with GRANT, optionally WITH GRANT OPTION, withdrawn with REVOKE; roles group privileges. Also: encryption and SQL-injection prevention.
