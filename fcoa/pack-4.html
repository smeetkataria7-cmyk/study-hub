Memory & instruction cycle

The hierarchy, cache mapping, the cycle in detail and virtual memory.
4.1

Memory hierarchy

LevelSpeedSizeCost / bit
RegistersFastestSmallestHighest
Cache (L1, L2, L3)Very fastKB–MBHigh

Secondary (SSD, disk)SlowTBLow

Going down the hierarchy: access time ↑, capacity ↑, cost per bit ↓, frequency of access ↓.

4.2

Memory characteristics

  • Capacity, access time, cycle time, transfer rate (bandwidth).
  • Access method: sequential, direct, random, associative.
  • Volatile vs non-volatile; erasable vs read-only.
  • Principle of locality: temporal (recently used data is used again) and spatial (nearby data is used next). The hierarchy and cache work because of locality.

4.5

Cache memory: concept

hit ratio  h = hitstotal accessesAMAT  thit + (1 − h) × tmiss penaltyeffective access time  h × tc + (1 − h) × (tc + tm)

A small, fast memory between CPU and main memory holding copies of recently used blocks. A hit finds the data in cache; a miss fetches the block from main memory.

4.6

Cache mapping techniques

  • Direct: memory block j maps to exactly one line, i = j mod L. Simple, but conflicts. Address = tag | line | word.
  • Fully associative: a block can go in any line; search all tags. Flexible, costly. Address = tag | word.
  • Set associative (k-way): block j goes to set j mod S, any line in the set. Address = tag | set | word.

4.8

Replacement and write policies

  • Replacement: LRU (least recently used), FIFO, LFU, random.
  • Write-through: write to cache and memory together (simple, slower).
  • Write-back: write to cache only and set a dirty bit; write to memory when the block is replaced.
  • Misses: compulsory (first use), capacity, conflict.
4.9

Instruction cycle in detail

  • Fetch: MAR ← PC; MDR ← M[MAR]; PC ← PC + 1; IR ← MDR.
  • Decode: the control unit interprets the opcode and addressing mode.
  • Indirect cycle (if needed): fetch the operand address, MAR ← IR(address); MDR ← M[MAR].
  • Execute: ALU operation, memory or I/O transfer, or branch (PC ← address).
  • Interrupt cycle: after execute, if an interrupt is pending: save PC (and flags) on the stack, load PC with the interrupt service routine address, run it, then restore and resume.
  • Role of registers: PC holds the next address, IR the instruction, MAR the memory address, MDR the data being transferred.

Q

Theory questions and model answers

Tap "Show model answer" to reveal.
Q1

Explain the memory hierarchy and the principle of locality.

Show model answer

Registers, cache, main memory and secondary storage: speed and cost per bit fall, capacity rises. It works because of temporal locality (used again soon) and spatial locality (neighbours used next).

Q2

Differentiate SRAM and DRAM.

Show model answer

SRAM stores a bit in a flip-flop: fast, no refresh, costly, used for cache. DRAM uses a capacitor and one transistor: dense and cheap but slower and needs periodic refresh, used for main memory.

Q3

Describe ROM, PROM, EPROM, EEPROM and flash memory.

Show model answer

ROM is programmed at manufacture; PROM once by the user; EPROM is erased by ultraviolet light; EEPROM electrically byte by byte; flash is erased in blocks (NOR for code, NAND for storage).

Q4

Explain the cache mapping techniques.

Show model answer
  • Direct: block j → line j mod L; address = tag | line | word.
  • Fully associative: any line; address = tag | word.
  • Set associative: set = j mod S; any line in the set; address = tag | set | word.
Q5

Explain write-through and write-back policies.

Show model answer

Write-through updates cache and memory together (simple, slow). Write-back updates only the cache and sets a dirty bit; memory is written when the block is replaced (fewer memory writes).

Q6

Explain the instruction cycle with the interrupt cycle.

Show model answer

Fetch (MAR ← PC; MDR ← M[MAR]; PC ← PC + 1; IR ← MDR), decode, optional indirect cycle, execute, and finally the interrupt cycle: if an interrupt is pending save PC (and flags) and load PC with the service routine address.

Q7

Compare paging and segmentation.

Show model answer

Paging uses fixed-size pages and frames, hidden from the programmer, with internal fragmentation. Segmentation uses logical variable-size segments with base and limit, visible to the programmer, with external fragmentation.

Practice problems with solutions

Try each one first, then open the solution.
P1

Cache address fields

A system has a 32-bit address, an 8 KB cache and 16-byte blocks. Find the lines, and the tag, line and word bits for a direct-mapped cache and for a 4-way set-associative cache.

Show solution
  1. Lines = 8192/16 = 512; word bits = log₂ 16 = 4.
  2. Direct: line bits = log₂ 512 = 9, tag = 32 − 9 − 4 = 19 bits.
  3. 4-way: sets = 512/4 = 128, set bits = 7, tag = 32 − 7 − 4 = 21 bits.
Direct: tag 19 | line 9 | word 4. 4-way: tag 21 | set 7 | word 4.
P2

Locating an address

In the direct-mapped cache of P1 find the tag, line and word for the address 0x1A2B3C4D.

Show solution
  1. Address = 00011010001010110011110001001101.
  2. Word = low 4 bits = 0xD; line = next 9 bits = 452; tag = remaining 19 bits = 0xD159.
Tag 0xD159, line 452, word 13.
P3

Direct-mapped cache trace

A direct-mapped cache has 4 lines. Memory blocks are requested in the order 0, 1, 2, 0, 1, 8, 0, 9. Find the hits and misses.

Show solution
  1. Line = block mod 4.
  2. block 0 → line 0: miss
  3. block 1 → line 1: miss
  4. block 2 → line 2: miss
  5. block 0 → line 0: hit
  6. block 1 → line 1: hit
  7. block 8 → line 0: miss (replaces 0)
  8. block 0 → line 0: miss (replaces 8)
  9. block 9 → line 1: miss (replaces 1)
2 hits and 6 misses out of 8 (blocks 0 and 8 both map to line 0, so they evict each other).
P4

Average memory access time

Cache hit time 1 ns, miss penalty 100 ns, hit ratio 95%. Find the AMAT. What if the hit ratio drops to 90%?

Show solution
  1. AMAT = hit time + miss rate × miss penalty.
  2. 95%: 1 + 0.05 × 100 = 6 ns.
  3. 90%: 1 + 0.10 × 100 = 11 ns.
AMAT = 6 ns at 95% and 11 ns at 90%: a 5% change nearly doubles the time.
P5

Page replacement

Reference string 7 0 1 2 0 3 0 4 2 3 0 3 with 3 frames. Count the page faults with FIFO and LRU.

Show solution
  1. FIFO: 7: fault [7]; 0: fault [7 0]; 1: fault [7 0 1]; 2: fault [0 1 2]; 0: hit [0 1 2]; 3: fault [1 2 3]; 0: fault [2 3 0]; 4: fault [3 0 4]; 2: fault [0 4 2]; 3: fault [4 2 3]; 0: fault [2 3 0]; 3: hit [2 3 0]
  2. LRU (list shows oldest first): 7: fault [7]; 0: fault [7 0]; 1: fault [7 0 1]; 2: fault [0 1 2]; 0: hit [1 2 0]; 3: fault [2 0 3]; 0: hit [2 3 0]; 4: fault [3 0 4]; 2: fault [0 4 2]; 3: fault [4 2 3]; 0: fault [2 3 0]; 3: hit [2 0 3]
FIFO: 10 faults; LRU: 9 faults.
P6

Paging arithmetic

A 32-bit virtual address with 4 KB pages. Find the offset bits, page-number bits and number of pages. Translate virtual address 0x00403A28 if page 0x403 is in frame 0x1F.

Show solution
  1. 4 KB = 2¹² → offset 12 bits.
  2. Page number = 32 − 12 = 20 bits → 2²⁰ = 1,048,576 pages.
  3. Address 0x00403A28: page = 0x403, offset = 0xA28.
  4. Physical = frame 0x1F, offset 0xA28 → 0x1FA28.
Physical address 0x1FA28.
